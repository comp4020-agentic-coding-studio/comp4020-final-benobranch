## Why

Starting [[ANU-029]], `pnpm run issue:start ANU-029` created a worktree
from `origin/main` (`0421edc`). Local `main` was 10 commits ahead, and
unpushed because `.githooks/pre-push` blocks the push until `pnpm check`
is clean, which the pre-existing map-balance failures prevent. So the
new worktree was missing [[ANU-019]], the issue's own just-committed file,
and the latest app changes. The script then crashed trying to flip
`issues/ANU-029.md` to `in-progress` in the worktree, because the file
didn't exist there. That left a half-set-up worktree, and re-running the
script exited early ("a worktree for this branch already exists").

The README's own flow ("open the issue on `main`, commit it, then
`issue:start`") guarantees the issue file is never on `origin/main` yet
unless you push in between, so on this repo the default path is broken
every time `main` is unpushed.

## Done when

- `scripts/issue-start.mjs` branches from whichever of `main`/`origin/main`
  is ahead, or always from local `main` when `origin/main` is an ancestor
  of it. Branching from local `main` is what `issues/README.md` assumes.
- A missing issue file in the new worktree fails *before* the worktree is
  created (or the script cleans up after itself), never half-way through.

## Notes

- Worked around for ANU-029 by `git reset --hard main` in the brand-new
  worktree (no work on it yet), then flipping status and `pnpm install` by
  hand.
