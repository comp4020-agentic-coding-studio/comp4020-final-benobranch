## Why

[[ANU-016]] and [[ANU-019]] finished the skill tree server-side
(`startResearch` message, per-player `skillTree` broadcast every ~1s,
`skillTreeVisual` pure function), but the client never handles the
`skillTree` message and no control sends `startResearch` — so in live play
the tree is invisible and unusable. ANU-013's "not yet player-controllable"
GUI boundary is lifted for the skill tree here, the same way [[ANU-020]]
lifted it for units/factories.

The user chose a 4th sidebar tab (next to Territory / Units / Factories)
over a full-screen overlay, and asked for the sourced Craftpix cyberpunk
skill icons — the "glitch white" set (pack folder `1 Icons/14`) only.

## Done when

- `app.js` stores the `skillTree` message and feeds it to the sidebar.
- A **Research** tab lists all nine nodes, each with its icon (copied from
  the pack's folder 14 into `server/public/icons/skills/`), a display name,
  a one-line effect description, and its state: unlocked / researching
  (with a progress bar) / available (with a Research button that sends
  `startResearch`) / locked (with the reason: prerequisite missing, or
  another node already researching). Prerequisite children render indented
  under their parent.
- Display names/descriptions live in `server/public/skill-tree-nodes.js`
  (shared source of truth), and `skillTreeVisual` passes them through along
  with a `lockedReason`.
- `data-uplink` is labelled as having no effect yet (its multiplier has no
  reader — ANU-016's Resolution).
- `spec/skill-tree-visual.test.ts` covers the new fields; full `pnpm check`
  green except the pre-existing map-balance / unitCatalog failures.

## Resolution

- **Research tab** (`sidebar.js` `renderSkillTree`/`buildSkillNode`,
  `index.html` `#panel-research`): one card per node with its icon, name,
  effect line, and state (Unlocked badge / progress bar with % / Research
  button / locked reason). `advanced-*` nodes indent under their chassis
  node with a connector line.
- **Data**: `skill-tree-nodes.js` gained `name`, `description`,
  `effectLive`, and `icon` is now a file path
  (`icons/skills/<node-id>.png`, copied from pack folder 14, plus
  `researching.png` for the progress row). `skillTreeVisual` passes these
  through and adds `lockedReason` (`"prerequisite"` beats `"busy"`).
- **Two nodes don't do anything yet**: `data-uplink` (expected, per
  ANU-016) and `rapid-capture`, whose `captureSpeedMultiplier` has no
  reader on `main` because [[ANU-017]] hasn't merged. Both carry
  `effectLive: false` and the card says "No in-game effect yet". Flip
  `rapid-capture` when ANU-017 lands.
- **Click-loss guard**: `skillTree` arrives every ~1s, so the list is only
  rebuilt when a node's state changes. Progress updates the bar in place,
  so a Research button isn't swapped out mid-click.
- **Existing bug fixed along the way**: `app.js` sent *every* `error`
  message outside the callsign prompt to Browse, so any rejected in-game
  action (`startResearch`, `attackSuburb`, `buildFactory`) kicked the
  player out of their game. While the sidebar is mounted, errors now show
  as a 5s alert at the top of the sidebar instead.
- `spec/skill-tree-visual.test.ts`: +6 cases (lockedReason
  prerequisite/busy/null, display fields pass through, data-uplink flagged,
  every icon path exists on disk). `pnpm check` against a server from this
  branch: 170 pass, 10 fail. All 10 failures already exist on `main`
  (map-balance ×9, economy-broadcast unitCatalog ×1).
- Not verified in a browser (CLAUDE.md's temporary no-manual-e2e rule).
