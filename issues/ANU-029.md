## Why

[[ANU-016]] and [[ANU-019]] finished the skill tree server-side
(`startResearch` message, per-player `skillTree` broadcast every ~1s,
`skillTreeVisual` pure function), but the client never handles the
`skillTree` message and no control sends `startResearch` — so in live play
the tree is invisible and unusable. ANU-013's "not yet player-controllable"
GUI boundary is lifted for the skill tree here, the same way [[ANU-020]]
lifted it for units/factories.

The user chose a 4th sidebar tab (next to Territory / Units / Factories)
over a full-screen overlay, and asked for the sourced Craftpix cyberpunk
skill icons — the "glitch white" set (pack folder `1 Icons/14`) only.

## Done when

- `app.js` stores the `skillTree` message and feeds it to the sidebar.
- A **Research** tab lists all nine nodes, each with its icon (copied from
  the pack's folder 14 into `server/public/icons/skills/`), a display name,
  a one-line effect description, and its state: unlocked / researching
  (with a progress bar) / available (with a Research button that sends
  `startResearch`) / locked (with the reason: prerequisite missing, or
  another node already researching). Prerequisite children render indented
  under their parent.
- Display names/descriptions live in `server/public/skill-tree-nodes.js`
  (shared source of truth), and `skillTreeVisual` passes them through along
  with a `lockedReason`.
- `data-uplink` is labelled as having no effect yet (its multiplier has no
  reader — ANU-016's Resolution).
- `spec/skill-tree-visual.test.ts` covers the new fields; full `pnpm check`
  green except the pre-existing map-balance / unitCatalog failures.
