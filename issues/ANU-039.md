## Why

The user noticed the Units tab (and, on inspection, the Territory tab's
suburb-detail heading and the Factories tab) show the raw `sal_code` ABS
area code (e.g. "80018") instead of the suburb's actual name (e.g.
"Ainslie"). `map.js` already resolves `sal_code -> name` for its own
tooltip (`sal_codeToName`, built in `initOnce()` from
`scripts/map/data/map.json`'s `suburbs` array, plus `cleanLabel()` to strip
the `" (ACT)"` suffix / rewrite `"ACT Remainder - X [part N]"` to
"Wilderness: X") — `sidebar.js` just never had access to that lookup and
fell back to the raw code everywhere it needed to label a suburb.

## Done when

- `map.js` exports a `suburbName(sal_code)` function (or equivalent) reusing
  `sal_codeToName`/`cleanLabel`, falling back to the raw `sal_code` if
  called before `initOnce()` has populated the map (same async-data-not-
  ready tolerance `groundCanReachSuburb`'s `adjacency` lookup already has).
- `sidebar.js` uses it everywhere a suburb is currently labelled by raw
  `sal_code`: the Territory tab's suburb-detail heading, the Units tab's
  per-suburb subheading ([[ANU-037]]), the Factories tab's "Factory @
  ..." line, the "Move units" panel's "Send to ..." button, and the
  non-owned-destination confirm prompt.
- `pnpm check` green.

## Resolution

Added `suburbName(sal_code)` to `server/public/map.js`, exported, reusing
the existing module-private `sal_codeToName` map and `cleanLabel()` helper
`describe()`/`showTooltip()` already used for the map's own tooltip; falls
back to the raw `sal_code` if `sal_codeToName` has no entry (not yet
loaded, or an unrecognised code), same tolerance `groundCanReachSuburb`
already has for `adjacency`.

`sidebar.js` imports it (alongside the existing `groundCanReachSuburb`
import — same cross-module pattern) and uses it at every spot that
rendered a raw `sal_code`: the Territory tab's suburb-detail `<p>` heading,
the Units tab's per-suburb `<li>` subheading, the Factories tab's "Factory
@ ..." line, the "Move units" panel's "Send to ..." button text, and the
`window.confirm` prompt for a non-owned attack destination.

No test changes needed: `spec/sidebar-view.test.ts` tests the pure
`suburbDetailViewModel`/`unitsByZone` view-model functions, which never
touched rendering text — `suburbName` itself lives in `map.js`, which
(per issues/ANU-020.md's Resolution) does `document.getElementById` at
module top level and isn't importable outside a real DOM, so it has no
direct unit coverage, same as the rest of map.js's rendering functions.
`pnpm check` — typecheck clean, 208/208 tests passing (unchanged).
