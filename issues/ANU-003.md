title: stray mock test server left listening on :8080 across tool calls
status: done
type: harness
opened: 2026-11-02

## Why

Testing the pre-push/`pnpm check` flow required something answering at
`APP_URL` (`spec/global-setup.ts` waits for it). A one-line Node HTTP server
was started in the background to stand in for the real app, which doesn't
exist yet.

## Done when

No server is left running after a round of manual testing, and the testing
approach doesn't rely on remembering to kill a background process across
separate tool calls.

## Resolution

Each shell command in this session runs in its own fresh process; a
`background` server started in one call and a `kill %1` issued in a later
call don't refer to the same shell, so the kill was silently a no-op. The
server from an earlier test was still listening on :8080 well after it was
believed stopped. The risk: a later `pnpm check` run would have passed
against that stale mock server rather than a real build, and
`scripts/record-check-ok.mjs` would have written a `CHECK_OK` marker that
looked legitimate but verified nothing real — exactly the kind of
false-positive the pre-push hook in [[ANU-001]]/[[ANU-002]] exists to
prevent, undermined at the source.

Caught by the same `advisor` review, which flagged it as a concrete risk
rather than a hypothetical. Confirmed with
`lsof -nP -iTCP:8080 -sTCP:LISTEN` (found the stray `node` process by PID)
and killed it directly, then re-verified `pnpm check` against a server
started and torn down within a single command (using a `setTimeout` to
self-terminate) rather than relying on a background job surviving across
calls.

## Notes

No harness rule was written for this one beyond this file — it's a testing
discipline note for this session rather than a rule the *app's* agent needs
going forward, since the real app won't be a hand-started mock server. Filed
as `type: harness` anyway because the mechanism (stale state producing a
false-positive check) is the same shape of problem [[ANU-001]]/[[ANU-002]]
address.
