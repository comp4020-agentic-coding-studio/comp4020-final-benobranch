## Why

The user pointed out that once a player accumulates lots of units at one
suburb, the Territory tab's suburb-detail occupant list
(`suburb-detail-view.js`'s `suburbDetailViewModel().occupants`, rendered by
`sidebar.js`'s `renderSuburbDetail`) renders one `<li>` per individual unit
— "Drone — Beno (3 hp)" repeated dozens of times — and asked for the same
archetype-grouped, count-badge treatment [[ANU-034]] already gave the map's
unit markers (fan out by archetype, show a live count instead of one icon
per unit).

## Done when

- `suburb-detail-view.js` gains an `occupantGroups` field on `SuburbDetail`:
  the selected suburb's occupants grouped by `(ownerPlayerId, unitTypeKey)`
  with a `count`, same shape/spirit as the existing `movableUnitGroups`
  (which is already grouped-by-type, just scoped to the viewing player's own
  units for the move panel rather than all occupants).
- `sidebar.js`'s `renderSuburbDetail` renders one row per group ("Drone —
  Beno ×12") instead of one row per unit.
- `spec/sidebar-view.test.ts` covers the grouping (multiple owners/types at
  one suburb, empty suburb).
- `pnpm check` green.

## Resolution

Added `occupantGroups` to `suburbDetailViewModel`'s return value
(`server/public/suburb-detail-view.js`), grouping `occupants` by
`${ownerPlayerId}|${unitTypeKey}` into `{ownerPlayerId, unitTypeKey, count}`.
`sidebar.js`'s `renderSuburbDetail` now iterates `detail.occupantGroups`
instead of `detail.occupants`, rendering `"<Type> — <owner> ×<count>"` per
group. Left `occupants` itself (the flat list) in place since
`spec/sidebar-view.test.ts`'s existing cases and no other caller needed it
removed. Two new test cases in `spec/sidebar-view.test.ts` cover grouping
across two owners/types at one suburb and the empty-suburb case.

## Notes

- [[ANU-034]] did the equivalent grouping for the map's unit markers
  (`unit-marker-layout.js`'s `layoutUnitMarkers`, grouped by `(sal_code,
  ownerPlayerId, archetype)`) — this issue applies the same idea to the
  Territory tab's text list, not the map, and doesn't touch
  `unit-marker-layout.js` or `map.js`.
- Per `CLAUDE.md`'s cost-discipline rule, no manual headless-Chrome
  verification performed — `pnpm check` is the bar.
