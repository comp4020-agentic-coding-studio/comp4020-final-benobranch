## Why

User request: mark each player's base with a skull icon, using the same
ownership-color system as units/factories ([[ANU-024]]'s colored-square
pattern). "Base" has no existing entity in this codebase — [[ANU-006]]'s
own Resolution explicitly dropped an earlier "home base" design in favor
of the current lobby spawn-suburb system (`spawn_table_by_lobby_size` in
`scripts/map/data/map.json`, applied at kickoff by
`server/territory.ts`'s `assignSpawnOwnership`). The closest existing
concept is **each player's originally-assigned spawn suburb**.

Confirmed with user: the skull marker should show only while the player
still owns that original spawn suburb — if it's captured by someone else,
the skull disappears (not reassigned to the new owner). This needs new
plumbing, not just a rendering change: today `assignSpawnOwnership` writes
a player's spawn suburb into the same `suburb_ownership` table as any
later capture, with nothing distinguishing "this was the original spawn"
once written — indistinguishable from a suburb captured mid-game. No
`PlayerPresence`/`LobbyState` field carries this to the client either.

## Done when

- **Schema**: a `spawn_sal_code TEXT` column added to `lobby_members`
  (migration alongside the existing `ALTER TABLE lobby_members ADD COLUMN`
  block in `server/store.ts`, ~line 436-443, following [[ANU-023]]'s
  now-fixed SQLite `ALTER TABLE` migration pattern).
- **Write path**: `territory.ts`'s `assignSpawnOwnership` (it already has
  each `memberPlayerIds[i] -> spawnSalCodes[i]` pairing in hand) also
  persists it to the new column, once, at kickoff.
- **Protocol**: `PlayerPresence` (`server/protocol.ts`) gains a
  `spawnSalCode: string | null` field, populated wherever `PlayerPresence[]`
  is built for `ServerLobbyState` broadcasts.
- **Rendering**: the skull icon (`Skillicon14_19.png` — icon 19, color 14,
  the same "glitch" white variant [[ANU-024]]'s unit icons use, confirmed
  by visual preview) draws at a player's spawn suburb's
  `label_point`, owner-colored square backdrop (same visual pattern as
  [[ANU-024]]'s unit markers / the existing factory marker), only rendered
  while `ownership[member.spawnSalCode] === member.playerId` — i.e. it
  disappears the moment that check fails, no special-case removal logic
  needed beyond the existing full-redraw-on-broadcast precedent
  `renderOwnership`/`renderUnits`/`renderFactories` already use.
- `spec/*.test.ts`: a player's base marker is present immediately at
  kickoff (spawn suburb = assigned suburb) and a test confirms it stops
  being "ownable" once that suburb changes hands (asserting against the
  new protocol field / store column directly is enough — no new e2e
  rendering test needed, consistent with the "no manual browser
  verification for now" CLAUDE.md rule).
- `pnpm check` passes (same pre-existing [[ANU-012]] map-balance failures
  excepted).
