## Why

PLAN.md's "Players & spawn balance" section commits to a specific, checkable
claim (equal shortest-hop distance from every home base to every data
center, baked once offline) but leaves two open decisions —faction count and
number of data centers— explicitly dependent on running the real search
against the real ACT road graph rather than picking numbers by feel. This
issue is that spike: build the real suburb-adjacency graph once (ABS SAL
tiles + OSM road adjacency, per PLAN.md's "Map data" section) and run the
balance search against it, so those two decisions are made from real numbers
before the map/combat subsystem is built on top of them.

## Done when

- A script (outside any worktree's deploy context until promoted — raw
  downloads live under a scratch dir, not committed) builds the ACT suburb
  adjacency graph: ABS SAL suburb polygons as nodes, edges where two suburbs
  share a road connection (not just a touching border), per PLAN.md's
  adjacency definition.
- A balance search runs over candidate faction counts and data center
  counts, reporting the best achievable hop-distance variance (and a
  reasonable spawn-separation / DC-separation constraint, since raw variance
  alone is trivially minimised by clustering) for each (faction count,
  data center count) combination.
- A short written verdict on which faction count and data center count to
  commit to, added to PLAN.md's "Open decisions" section (resolving those
  two bullets), with the actual numbers behind the call.
- The chosen configuration (adjacency graph + spawn suburb ids + data
  center suburb ids) is baked into a committed derived-data file, with
  source attribution (ABS SAL CC BY 4.0, OSM ODbL) recorded alongside it.
- A `spec/*.test.ts` check loads that baked file and recomputes hop-distance
  variance from the adjacency list directly (not from a stored precomputed
  number), asserting it's within the tolerance the verdict settled on —
  this is the enforceable claim PLAN.md flags as exactly the kind of thing
  worth pointing at directly rather than just asserting.
