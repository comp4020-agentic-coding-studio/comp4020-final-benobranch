## Why

Found while verifying `pnpm check` for [[ANU-019]] (unrelated branch): the
full test suite fails on `main` with

```
spec/economy-broadcast.test.ts > hello yields a unitCatalog with the real seeded drone/robot stats, not placeholders
AssertionError: expected { key: 'robot', health: 10, ... } to match object { health: 6, ... }
```

Root cause: commit `9a2b164` ("updated robot health") bumped
`server/units.ts`'s `seedBaseUnitTypes` robot health from 6 to 10, but never
updated `spec/economy-broadcast.test.ts`'s matching `toMatchObject({ health:
6, ... })` assertion. That commit also doesn't follow the repo's
`ANU-NNN: <summary>` message convention (`docs/git-workflow.md`/
`issues/README.md`), so it's not linked to any issue and slipped past
`pnpm check` being run before push (or was pushed without it, which the
pre-push hook's marker check should ordinarily have caught against a dirty
tree, but wasn't flagged in the branches checked against this).

Confirmed pre-existing and unrelated to [[ANU-019]]: reproduced on a plain
`main` checkout before that branch's changes, with no diff to
`server/units.ts` on that branch.

## Done when

- `spec/economy-broadcast.test.ts`'s expected robot health matches
  `server/units.ts`'s actual seeded value (10), or vice versa if 10 was
  itself a mistake — whichever reflects the real intended balance number.
- `pnpm check` passes this test on `main`.
- No regressions.
