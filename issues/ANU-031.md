## Why

The sidebar's `0 TFLOPS` counter (`#sidebar-tflops`, `server/public/sidebar.js`)
already shows [[ANU-019]]'s live, derived TFLOPS figure (the sum of
currently-held data centers, recomputed from `suburb_ownership` — never a
stored balance). Mechanically it's already correct: the `economy` broadcast's
`tflops` field is the live number, not a leftover balance.

The user's complaint is about **presentation, not the number's source**: the
counter is still styled and positioned as `sidebar-economy`'s second
"currency" line, sitting next to `scrap` (`server/public/index.html`'s
`<p id="sidebar-economy">`) as if it's a resource you bank and spend
alongside it. [[ANU-019]] killed that model — a data center's TFLOPS is a
*speed multiplier* on skill-tree research
(`server/skill-tree.ts`'s `speedMultiplier = 1 + tflops/100`), not a second
currency. Scrap is the only resource actually spent (PLAN.md's "Two
resources" section). Showing them as two peer line items in the same pill
misrepresents what TFLOPS *does* — the user wants to see the TFLOPS figure
specifically where it matters: next to the resulting research multiplier,
on the Research tab, so holding a data center visibly speeds up whatever's
being researched.

`speedMultiplier` is currently private to `server/skill-tree.ts` — nothing
in the broadcast protocol exposes the multiplier itself today, only the raw
`tflops` figure (`ServerEconomy.tflops`, `ServerSkillTree.tflops`). Showing
"the resulting research multiplier" next to TFLOPS means either computing
`1 + tflops/100` client-side (duplicating a formula PLAN.md already flags as
open tuning — risks drifting from the server's own curve if either changes
independently) or exposing it from the server alongside `tflops`/
`researching` in the existing `skillTree` message. The latter keeps the
curve in one place.

## Done when

- The sidebar's top-level `sidebar-economy` pill (`server/public/index.html`)
  shows **scrap only** — TFLOPS is no longer rendered as a second currency
  line there.
- The **Research tab** (`panel-research`) shows the player's current live
  TFLOPS figure and the resulting research-speed multiplier it produces,
  visible regardless of whether a node is currently researching (so a
  player can see what holding more data centers would buy them even with
  nothing queued) — not just baked into the in-progress node's existing
  progress bar.
- `server/skill-tree.ts`'s `speedMultiplier` curve is exposed through the
  `skillTree` broadcast (`ServerSkillTree` in `server/protocol.ts`) rather
  than reimplemented in `server/public/skill-tree-visual.js` — one source of
  truth for the curve, same reasoning PLAN.md already gives for keeping it
  server-side tunable.
- `spec/skill-tree-protocol.test.ts` covers the new field landing in the
  broadcast; `spec/skill-tree.test.ts` or a sibling covers that it tracks
  `speedMultiplier`'s existing formula (a mega data center alone yields 2x,
  matching the test already in place for the research-time math).
- No regression to the existing `0 TFLOPS` map-marker tooltip text
  (`server/public/map.js`'s `${dc.tier} data center — ${dc.tflops} TFLOPS`)
  or the map legend — this issue is scoped to the sidebar/Research-tab
  readout only, not every place "TFLOPS" appears in the UI.
- `pnpm check` green (typecheck + `spec/*.test.ts` against the running app —
  per `CLAUDE.md`'s cost-discipline note, no manual browser verification
  required for this pass).

## Notes

Raised directly by the user from a screenshot of the live sidebar

tree." Builds on [[ANU-019]] (live TFLOPS derivation — unchanged by this
issue) and [[ANU-029]] (the Research tab this moves the readout into).
