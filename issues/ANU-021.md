## Why

The map's data-center markers (`.dc-marker--mega/major/standard` in
`server/public/map.js`/`map.css`) are currently plain solid-color SVG
circles. A free asset pack (`Free-Skill-32x32-Icons-for-Cyberpunk-Game`,
craftpix license, see its `License.txt`) ships the same icon in 14 color
variants; icon 35 reads as a small facility/server glyph. Swapping the
circles for that icon (recolored per tier) makes data centers read as
distinct map objects rather than undifferentiated colored dots, matching
the tier-marker-radius distinction (`MARKER_RADIUS`) with a visual one.

## Done when

- The three tier icons (`Skillicon<n>_35.png`, 32x32, color 9 for standard,
  color 1 for major, color 12 for mega) are copied into
  `server/public/icons/` under clear names, same 32x32 size, served by the
  existing static-file route.
- `map.js`'s data-center layer renders an `<image>` per data center at that
  icon (sized/centered on the suburb's `label_point`, replacing the
  `<circle class="dc-marker--...">` element) instead of a solid circle.
- `map.css`'s `.dc-marker--mega/major/standard` fill rules and the map
  legend's `.legend-dot--*` swatches are updated to match (legend can keep
  a colored dot or also switch to a tiny icon — just stay visually
  consistent with the new marker).
- `pnpm check` passes.

## Resolution

Copied the three tier icons (color 9/standard, 1/major, 12/mega, icon 35)
into `server/public/icons/` at their native 32x32 size, and added `.png` to
`server/static-files.ts`'s served MIME types so they're reachable.
`map.js`'s data center layer now renders an SVG `<image>` per data center
(2x the old circle radius as width/height, `image-rendering: pixelated`)
instead of a `<circle class="dc-marker--...">`; the per-tier icon path/size
constants live in a new dependency-free `server/public/data-center-visual.js`
(same file-layout convention as `unit-visual.js`/`factory-visual.js`) rather
than inline in `map.js`, so a plain Node test can import the color constant
without a DOM. `map.css`'s `.dc-marker--*` fill rules are gone (an `<image>`
has no `fill`); the legend's `.legend-dot--*` swatches now show the actual
icon via `background-image` instead of a flat color.

Found along the way: the icon pack's standard (teal) and mega (crimson)
tints land within a few degrees of hue of this lobby's own teal/crimson
`PLAYER_COLORS` entries, which broke `spec/territory.test.ts`'s existing
25-degree-hue / 60-RGB-distance "data-center marker colors must be
disjoint from player colors" guarantee — not achievable at this color-pack
choice. Per explicit user sign-off, loosened that test rather than picking
different icon colors: split it into a pairwise-player-color-distinctness
check (unaffected by marker color, still enforced at the old bound) and a
much weaker "no player color exactly duplicates a marker color" check,
noting that markers are now also shape-differentiated (a distinct glyph per
tier), which was most of what the original guarantee was protecting against.

`pnpm check` run against this branch's own dev server: same 9 pre-existing
`spec/map-balance.test.ts` failures as a clean `main` checkout ([[ANU-012]],
not this issue's regression — all 20 other test files, including the
updated `spec/territory.test.ts`, pass).
