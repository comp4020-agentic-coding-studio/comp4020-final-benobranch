## Why

Players need an actual interface to the backend ANU-005 shipped — right now
`server/public/index.html` is a bare inline-script test page (plain inputs
and `<span>`s), not something built for the marker constraints
(`docs/git-workflow.md`'s art-direction source, PLAN.md's "Art direction"
section: dark, high-contrast, HUD-style chrome; legible at phone width).

ANU-006 (map preprocessing: faction count, data-center placement, the real
suburb/road adjacency graph) is still in progress on its own branch and
hasn't landed any committed suburb list or game-state shape yet — so there
is no real map/game data to build a board against today. Rather than block
on it or build against placeholder geography that would need reworking, this
issue builds the GUI shell against what's actually committed: the ANU-005
`server/protocol.ts` WebSocket contract (`hello`/`welcome`/`presence`/
`bump`/`counter`). It replaces the throwaway test page with a real HUD —
join flow, live player list, connection-state handling — styled per the
art direction, so the moment ANU-006's game state lands, it has a UI
foundation to render into instead of starting from inline `<script>` tags.

## Done when

- `server/public/` holds a real client (plain ES modules — the server has no
  build step and browsers can't run TypeScript, so this stays consistent
  with that rather than introducing a bundler for a GUI this small) styled
  per PLAN.md's art direction: dark base, high-contrast HUD chrome, legible
  at phone width (test at both marking viewports — a narrow one and a
  standard desktop one).
- A join screen (name entry) that sends `hello` and transitions to the HUD on
  `welcome`, per `server/protocol.ts`.
- The HUD shows: the live player list (updates on every `presence`
  broadcast), the shared counter and who last bumped it (updates on every
  `counter` broadcast), and this client's own connection state (connecting /
  connected / disconnected, since a dropped WebSocket shouldn't look
  indistinguishable from a live one — relevant for "it's good" under bad
  connections, per the brief's top band).
- Two browser profiles (e.g. two incognito windows) open at once each show
  the other joining/leaving and bumping in real time, with no reload —
  manually verified before calling this done, per the brief's actual marking
  method.
- `spec/*.test.ts` covers what's mechanically checkable from the served HTML
  (e.g. the join form and HUD containers are present in the markup) — the
  realtime *behaviour* is already covered by `spec/realtime.test.ts`; this
  issue doesn't duplicate it, just makes sure the page the browser actually
  loads has the right structure.
- No regressions: both existing `spec/invariants.test.ts` checks and the
  ANU-005 specs (`spec/persistence.test.ts`, `spec/realtime.test.ts`) still
  pass unmodified.

## Resolution

Built a plain-ES-module client in `server/public/` (`index.html`, `style.css`,
`app.js`): a join screen (callsign entry → `hello`) that transitions to a HUD
on `welcome`, showing the live player list (highlighting the viewer's own
row), the shared counter and last-bumped-by, and a status bar reflecting
connecting/connected/disconnected. Reconnects on drop with exponential
backoff, re-sending `hello` on reopen since the server assigns a fresh
`playerId` per connection and rejects any action before `hello` (matches
`server/index.ts`'s existing 1008-close behaviour).

`app.js` is typed via `// @ts-check` + JSDoc against `server/protocol.ts`
(tsconfig's `allowJs: true`), so `pnpm typecheck` catches a client/server
message-shape drift instead of only being caught in the browser.

Added `server/static-files.ts` (the server previously only routed the exact
strings `/` and `/readme/`; a multi-file client needs real static serving) —
resolves against `PUBLIC_DIR`, rejects path traversal, and maps extensions to
MIME types explicitly (`.js` as `text/javascript`, since browsers refuse
`<script type="module">` on the wrong content-type with no console error
pointing at why). Also added a server-side ping/pong heartbeat
(`server/index.ts`) to terminate sockets that stop responding without firing
`close` (a dropped wifi connection or a sleeping phone), so the "Online" list
doesn't accumulate ghost entries, and capped `hello`'s name length in
`protocol.ts` (1–40 chars) since names are untrusted input rendered via
`textContent` to every connected client.

Verified with headless Chrome driven over the DevTools Protocol (plain
`--window-size` does not reliably clamp the headless viewport — confirmed via
`Runtime.evaluate` reading `window.innerWidth`; switched to
`Emulation.setDeviceMetricsOverride` for accurate 390×844 / 1920×1080
emulation, the two marking viewports per the course site's assessment topic):
- Two independent tabs joining as different names each see the other in
  presence, each highlights its own row correctly, and a bump from one is
  reflected in the other's counter and "last bumped by" within the same
  check — i.e. multi-user and real-time together, not just each in isolation.
- No horizontal overflow at 390×844.
- Caught and fixed a real bug this way: the HUD screen rendered underneath
  the join screen before joining, because `.screen[hidden]` needs restating
  explicitly — the UA stylesheet's default `[hidden] { display: none }` and
  this app's `.screen { display: flex }` tie on specificity, and the
  later-loaded stylesheet wins the cascade.

`pnpm check` passes locally and against a container built from the
(unchanged) `Dockerfile`, run the same way CI's `check` job does
(`--init --tmpfs /data`).

## Notes

Scoped deliberately narrow: no map rendering, no suburb/faction visuals —
that depends on ANU-006's output, which isn't committed yet. This is the
chrome and connection-handling layer those will render into.

Ran locally on localhost for the user to look at directly before merging
(per docs/git-workflow.md rule 6, on a scratch port/DATA_DIR distinct from
main's); approved as-is ("looks good") with no changes requested.
