## Why

[[ANU-013]] stubbed a per-member `tflops`/`tflops_last_accrued_at` column
pair ("the balance itself; real accrual logic is explicitly out of scope
here") and flagged that a future issue would need to implement real accrual
using the same stored-timestamp pattern as capture/production/travel.
[[ANU-016]] (the skill tree) built real purchase logic on top of that
balance — `purchaseNode` deducts TFLOPS synchronously and is covered by
`spec/skill-tree.test.ts`/`spec/skill-tree-protocol.test.ts` — but no issue
has picked up the accrual half. In live play every member's `tflops` stays
at 0 forever (nothing ever credits it), so `purchaseNode` always returns
`insufficient-tflops` and the skill tree is only reachable in tests that
directly `UPDATE lobby_members SET tflops = ...` against the store. The
feature is built but not playable.

**Scope changed before work started, on direct correction from the user.**
The analysis above (and [[ANU-016]]'s original design, and PLAN.md's "Two
resources" section as [[ANU-013]] had revised it) all read TFLOPS as a
*balance* — something a player accrues and then spends on skill-tree nodes.
The user clarified directly that this was never the intended design: a data
center's TFLOPS rating is meant to speed up the skill tree's unlock rate,
not fund it as a currency. So "implement accrual so the existing spend-based
`purchaseNode` has a live balance to check" is the wrong fix — there is
nothing to accrue or spend. This issue instead redesigns [[ANU-016]]'s
purchase mechanic into time-gated research, and makes TFLOPS a live,
derived number rather than a stored balance at all.

## Done when

- TFLOPS becomes a **live, derived value**, not a stored/accrued balance:
  `server/tflops.ts`'s `getTflops(lobbyId, playerId)` sums the TFLOPS rating
  of every data-center suburb a player currently owns (via
  `suburb_ownership` + `scripts/map/data/map.json`'s `data_centers` list),
  recomputed at read/broadcast time. [[ANU-013]]'s
  `tflops`/`tflops_last_accrued_at` columns are dropped (migration v8) as
  dead weight under this model.
- `server/skill-tree.ts`'s purchase mechanic is replaced with **time-gated
  research**: starting research on a node (`startResearch`, replacing
  [[ANU-016]]'s `purchaseNode`) is free and always succeeds once its
  prerequisite is met and nothing else is already researching (one active
  research slot per player, confirmed with the user — not a queue); the node
  unlocks on its own once its base research time, divided by the player's
  current live-TFLOPS-derived speed multiplier, has elapsed — computed
  lazily via `server/time.ts`'s `elapsedMs` against a stored
  `skill_research.started_at`, never an armed timer, same pattern
  `server/factories.ts`'s production cycles already use.
- `spec/*.test.ts`: a player holding a data center (`spec/tflops.test.ts`)
  gets exactly that data center's TFLOPS, summed correctly across several,
  live (ownership change reflected immediately, no stored state);
  `spec/skill-tree.test.ts` covers starting research, prerequisite/
  already-unlocked/already-researching rejections, a node completing once
  enough elapsed time has passed at the held TFLOPS's speed, and a restart
  test (`spec/skill-tree-restart.test.ts`, styled on
  `spec/factories-restart.test.ts`) proving research in progress survives a
  real process restart; `spec/skill-tree-protocol.test.ts` covers
  `startResearch` end-to-end over the real WebSocket, including — now
  possible for the first time, since nothing needs funding before
  research can start — a genuine success-path broadcast.
- No regressions: full `pnpm check` green except the pre-existing, unrelated
  [[ANU-012]] map-balance failures (and one pre-existing, also-unrelated
  `spec/economy-broadcast.test.ts` robot-health fixture mismatch, confirmed
  present on `main` before this branch).

## Resolution

Redesigned rather than just filled in, per the user's direct correction
(see "Why" above): TFLOPS is now computed live by `server/tflops.ts` from
currently-held data centers (PLAN.md's "Data centers"/"Two resources"
sections rewritten to match), and `server/skill-tree.ts`'s `purchaseNode`
became `startResearch` — free to start, time-gated to complete, speed scaled
by that live TFLOPS reading via a `speedMultiplier = 1 + tflops/100`
placeholder curve (a mega data center alone doubles speed; PLAN.md still
lists the exact curve as open tuning). `skill_nodes`'s existing per-player
unlock table is unchanged; a new `skill_research` table
(`lobby_id, player_id, node_id, started_at`, one row per player) tracks the
single in-progress node, settled lazily the same way
`factory_production.cycle_started_at` is, including from the existing 1s
factory ticker (extended to also settle+push each lobby member's skill-tree
state, not a second interval).

`server/protocol.ts`'s `purchaseNode`/`ServerSkillTree.tflops`-as-balance
were renamed/reworked (`startResearch`; `ServerSkillTree` gained
`researching`), and the client-side pure module
`server/public/skill-tree-visual.js` dropped its TFLOPS-affordability check
in favour of a `researching` state (a prereq-met node is locked, not
purchasable, while any node — including itself — is being researched).
[[ANU-016]]'s own node list/perk-effect bindings (`PERK_EFFECTS`,
`seedSkillGatedUnitTypes`) were left unchanged; only the gate on when a
node's effect applies moved from "balance check passes" to "elapsed time
passes."

`pnpm check`: typecheck clean, `check:issues` clean, full test suite green
except [[ANU-012]]'s pre-existing map-balance failures and one pre-existing
`spec/economy-broadcast.test.ts` fixture mismatch (confirmed present on
`main` before this branch, unrelated to this change — a stale expected
robot health value after an unrelated balance tweak).

## Notes

Originally opened as a straightforward "implement the missing accrual half"
bug against [[ANU-016]]'s spend-based design — see [[ANU-016]]'s Notes for
that original framing. Re-scoped on direct user correction before
implementation began: TFLOPS/data centers were never meant to be a
currency, so accrual (crediting a balance) was the wrong fix for "the skill
tree is unreachable in live play" — the actual fix was removing the balance
concept entirely in favour of a live speed multiplier, which also removes
the need for any accrual logic at all. [[ANU-016]]'s Resolution section is
left as the historical record of what shipped then; this issue's Resolution
is what's live now.
